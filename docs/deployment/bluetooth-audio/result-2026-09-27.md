# Raspberry Pi 5 Bluetooth audio result — 27 September 2026

Basic Bluetooth speaker playback was accepted on the development Pi 5 with an Anker Soundcore. A reviewed signed transaction installed BlueZ, PipeWire, PulseAudio compatibility, WirePlumber and ALSA utilities: 40 additions and 12 upgrades, with 387 packages afterward. Bluetooth and the user audio services are enabled and active. The speaker is bonded, trusted and connected using A2DP SBC, and selected as the default output. The operator confirmed a 15-second continuous clip played through ordinary application audio without an explicit device override or reconnect.

Short clips following idle were sometimes inaudible despite running, unmuted streams and an active Bluetooth transport. The operator reports similar behavior with this speaker on other devices and accepted sustained playback as the basic audio milestone. The exact cause was not established. Reconnection reused the existing bond. Mute/unmute state changes passed software checks; the corresponding audible pattern was not independently confirmed. This is a single-device result, not general Bluetooth hardware certification.

The package transaction preserved the checked access, encryption and boot configuration, PCIe Gen1 setting and USB-first EEPROM order; its identified vendor authentication-policy update was explicitly approved. Recovery material was verified off-device. The installed kernel is 6.18.53-1, while this session still runs 6.18.52-1-rpi. No reboot was performed. Browser playback, desktop pairing/output/volume controls and reboot persistence remain open. Browser support and a pleasant Omarchy desktop take priority over publishing disk images; see the [desktop milestone](../pi5-minimal-install.md#desktop-experience-before-images).
