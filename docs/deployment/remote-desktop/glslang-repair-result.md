# Hyprland loader repair and recovery baseline — 23 September 2026

The first bounded RDP operator run stopped in **read-only preflight**, before tty8, Hyprland, hypr-rdp or a network listener started. `Hyprland --verify-config` could not load a glslang shared library. `ldd /usr/bin/Hyprland` identified `/usr/lib/libglslang-default-resource-limits.so.16` with an unsupported ELF `Verneed` version. The actual regular file is `/usr/lib/libglslang-default-resource-limits.so.16.4.0` in `glslang 1:1.4.357.0-1`; `pacman -Qkk glslang` reported it as the package's sole checksum mismatch. The Hyprland package itself had zero altered files.

A full unprivileged `pacman -Qkk` found no other confirmed package-content checksum mismatch. Most reported `/boot` mode/time differences are expected on its FAT filesystem. Several protected root-owned files could not be hashed as Sierra; their unreadable status is not evidence of changed contents. The current boot journal had no matching NVMe, ext4 or I/O error. This does **not** establish why the glslang bytes changed: 8,159 differing byte positions occupied an 8,192-byte span of the 67,496-byte file, and its ctime remained the original package-install time. A storage or write-path problem remains possible.

The exact aarch64 `glslang 1:1.4.357.0-1` archive was downloaded into private scratch space without refreshing the live pacman database. Its SHA-256 `f2415c238ca8299f9f31ae87c263d4ceb269364b0826e91f5fc9a1fefbaac243` matched the existing sync database. The detached signature matched the sync DB's `%PGPSIG%` field and verified with full trust against the Arch Linux ARM Build System key, fingerprint `68B3537F39A313B3E574D06777193F152BDBE6A6`. The archive member SHA-256 `12b4359e15f10a35d3206c1ac9dfe808dd21d23fb176f5c132cae30e649f17e6` matched the local pacman mtree digest; the installed file had SHA-256 `e042a943395c7a035527995202196acc80aff9eccc721c9bc3d79ab18f1cce0b`.

Only that one regular file was replaced. The repair ran as root after checking package version, archive hash/signature, member hash, metadata, symlink target, pacman lock absence and same-filesystem staging. It preserved the damaged inode as a hard link at `/var/lib/omarchy-pi-deploy/20260923T101627Z/glslang-repair.h7T6eaEo/original.so`, then atomically renamed the verified archive member into place. The root-only stage retains the signed archive, signature, original inode and verification reports. No pacman package transaction or service change occurred.
