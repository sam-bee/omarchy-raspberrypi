# Pi 5 image viewing and backgrounds — 27 September 2026

The encrypted NVMe Pi now has Files (Nautilus), imv, thumbnail generation and Qt image-format plugins. The active session release is `5820c81d`; package-policy follow-up `69cc14b0` adds the runtime needed by the HEIF backend. Both changes are on `quattro-rpi5`.

Users can open Files with `Super+Shift+F`, open an image in imv, and press `Ctrl+B` to use it as their background. `Super+Ctrl+Space` or a left double-click on the desktop opens the background picker. The Pi picker and cache warmup accept still images only. Existing imv configurations are preserved, so the setup helper seeds the Ctrl+B binding only on a fresh profile. See the [image setup procedure](pi5-minimal-install.md#image-viewing-and-background-selection).

Installing the plugin fixes the shell's decoder; `libvips` supplies picker thumbnails. The reproducible `still-image-desktop` package profile also includes imv, Nautilus, the GTK chooser/Python bindings, jq, ImageMagick and the explicit PipeWire JACK provider.

The first signed transaction installed 151 packages and upgraded four existing packages: `ca-certificates-mozilla`, `fribidi`, `nss` and `rpi5-eeprom`. The GTK portal was already present. A separately reviewed, signed `rav1e 0.8.1-3` installation fixed that warning. All ten profile roots are installed; the resulting system has 581 packages. HEIF backend initialization passed, but HEIF/AVIF sample-image rendering was not separately exercised.

Nautilus brings gvfs/udisks2/mdadm dependencies; firmware files in the reviewed EEPROM package triggered the existing initramfs hook. The regenerated image retained the prior boot/unlock binaries and kernel modules. Its only file-content differences were the regenerated hardware database and a v4l-utils infrared-keymap systemd drop-in. A verified encrypted backup of configuration, boot files, modules and package metadata was retained before installation. Previous versions of the four upgraded packages were retained for reviewed rollback.

No EEPROM update was applied. Boot order, existing staged firmware files, boot configuration, account/authentication files and LUKS metadata were unchanged. No reboot occurred; the running kernel remains `6.18.52-1-rpi` and the installed `6.18.53-1-rpi` kernel/initramfs still needs reboot acceptance.
