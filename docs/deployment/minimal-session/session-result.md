# Pi minimal Omarchy session result — 23 September 2026

**Result:** a bounded local UWSM session rendered Omarchy's workspace/clock bar and a mapped Foot terminal on the Raspberry Pi 5. The reviewed `start-hyprland` wrapper removed the direct-launch warning. `grim` captured the headless Wayland output on the Pi and the PNG was copied over SSH; no RDP client or server was used. The session was stopped after capture; no graphical login, autologin, service or unit was enabled. This proves a visible minimal headless desktop, not a complete Omarchy workstation.

All four attempts restored VT1 and stopped the named transient service. The final wrapper run stopped only `wayland-wm@start\x2dhyprland.service` after verifying its wrapper `MainPID`; the recorded Hyprland child, Quickshell and Foot exited. UWSM cleared its session environment. The post-stop journal showed orderly unit and target shutdown and no observed wrapper abort or coredump. A separate fresh SSH login confirmed the encrypted NVMe root, `/boot`, Wi-Fi address and route, active SSH/networkd/WPA services, no tty8 session, graphical user unit, Wayland socket or graphical process. The independent recovery check passed all 30 preservation checks against the private backup, including protected hashes/account exceptions, USB unlock key, LUKS metadata, EEPROM, package counts/reasons and inactive Avahi/Fumon units.

The visible milestone is a working **minimal local headless session**. HDMI output, normal login, portals, audio, idle/lock, network UI, screen sharing and remote desktop remain untested. Quickshell logged a nonfatal host-portal registration warning; that is not evidence of portal functionality. Before making this a persistent desktop, review those integrations and the visible Hyprland logo, then repeat a bounded visual test.
