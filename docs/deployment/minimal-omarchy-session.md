# Draft Pi UWSM and Quickshell session

This is a source-only draft for the step after the bounded Hyprland/Foot smoke. It has not been installed or launched on the Pi. Fresh package closure, archive/hook review, and the smoke result must precede deployment. It does not install packages, enable services, change boot/network configuration, or arrange automatic login.

## Scope and source layout

`install/arm64/stage-user-session.sh` runs as `sierra`, from a clean committed checkout on the target. It records one commit ID and archives that immutable revision to `~/.local/share/omarchy-pi/releases/<commit>/`, creates `~/.local/share/omarchy-pi/current` as a symlink to the release, and publishes four new user-owned files. It refuses an existing release, current link, or destination file, including dangling symlinks. An exclusive per-user lock refuses concurrent staging. Each config file is prepared under a temporary name in its destination directory and hard-linked into place with atomic create-if-absent semantics. The current symlink is also hard-linked from a temporary symlink, allowing failure cleanup to identify its inode even if interrupted immediately after publication. Cleanup removes only unchanged files and links created by that run; a promoted release is retained for inspection rather than recursively deleting files another process may have added. The script has no `sudo`, `pacman`, or `systemctl` action. Because Quickshell in this source uses `$HOME/.config` directly, the stager rejects a nondefault `XDG_CONFIG_HOME` before writing.

| New user file | Purpose |
| --- | --- |
| `~/.config/uwsm/env.d/90-omarchy-pi` | Set `OMARCHY_PATH`, prepend its `bin`, select `xdg-terminal-exec` |
| `~/.config/hypr/hyprland.lua` | Load Quattro's Lua defaults with bounded startup and a Foot terminal binding |
| `~/.config/omarchy/shell.json` | Clock/workspace bar; disable `omarchy.idle` while its screensaver is unavailable |
| `~/.config/xdg-terminals.list` | Select `foot.desktop` |

[UWSM sources user `env.d` files after lower-priority data directories](https://github.com/Vladimir-csp/uwsm/blob/master/README.md), so the user-owned release path overrides a packaged default if present. The session does not rely on `/usr/share/omarchy`, `/etc/omarchy.conf`, or a display manager. The source archive contains the committed Omarchy tree, including commands, shell plugins, Lua defaults, themes, and config assets; it excludes Git internals and unrelated files outside this repository.

The normal Omarchy autostart remains unchanged by default. The Pi overlay sets `omarchy_autostart_minimal` before loading `default.hypr.omarchy`. In that mode startup imports the graphical environment into the user manager and D-Bus, then invokes `start-shell.sh`. The helper holds a lock for the compositor instance, queries its active outputs, creates one headless output only if none exists, and waits up to five seconds for an output before launching the single Omarchy Quickshell process. This reflects the Pi smoke finding: Hyprland 0.56.2 did not create `HEADLESS-0` automatically with both HDMI ports disconnected, and its start callback ran before Foot could map. The helper skips output creation when a physical output is already active. Runtime validation must still confirm UWSM passes the correct instance signature and that the helper can query that instance. Minimal mode skips first-run provisioning, power-profile initialization, monitor watcher, `udiskie`, and post-boot hooks. The overlay disables bundled keybindings and supplies only `Super+Return` through `uwsm-app -- xdg-terminal-exec`, avoiding actions for applications absent from this package stage.

Every first-party service is disabled through the shell's supported `disabledPlugins` setting for the first launch: background, lock, notifications, polkit, battery, idle, media, and nightlight. The UWSM environment also sets `OMARCHY_PI_MINIMAL_SESSION=1`. The shell uses that flag to select a minimal built-in bar before its asynchronous config files load and to prevent `_syncServices` from creating any service during the entire minimal session. This closes the startup window before `shell.json` is read. It prevents the excluded `ttfx` screensaver and unvalidated service dependencies from starting. A persistent interactive deployment needs a tested idle/lock path before the Pi is used unattended. Enable services one at a time after package and runtime checks; this requires retiring the minimal-session flag in a separate reviewed step. The initial bar excludes the NetworkManager-backed network widget, audio until PipeWire is validated, and menu actions that still expose x86/network setup paths.

## Local validation and later Pi acceptance

Run `bash test/shell.d/arm64-minimal-session-test.sh` from the draft branch. The functional test stages from a clean temporary checkout, so it still works when the development worktree is dirty. It checks the user files, link, lock refusal, create-if-absent publication against a simulated competing writer, partial-failure cleanup, dirty-source refusal, and headless helper with stubbed compositor commands. A focused source invariant checks that minimal mode selects the initial bar before registry scanning and gates service creation regardless of config-load order. It does not start a compositor or Quickshell. The Pi package stage must include `uwsm`, `quickshell`, `xdg-terminal-exec`, `inotify-tools`, and Qt Wayland support, with exact dependency closure and hooks reviewed there. The previous smoke stage already supplies Hyprland, Foot, and the terminal font if it passes.

Before a bounded tty8 UWSM launch, validate `Hyprland --verify-config --config ~/.config/hypr/hyprland.lua`, `xdg-terminal-exec --print-id`, the UWSM environment, and preservation of SSH/networkd. During the launch check `hyprctl configerrors`, the compositor's monitor/client state, `omarchy-shell shell ping`, bar logs, and a fresh independent SSH connection. Stop the named experiment, restore its VT, and repeat substrate checks. No UWSM or Quickshell runtime result is claimed by this draft.

## Removal

After stopping only the test session, inspect the four user files and the `current` symlink target. If they still match this staged release, remove those five paths and `releases/<commit>` only. Leave any user-edited file or a retained partial release for review instead of deleting it. The stage lock file can be removed after confirming no staging process holds it. The stage command creates no package or system service state to undo. Removing the overlay does not roll back the separately reviewed package transaction.
